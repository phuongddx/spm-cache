<objective>
Complete FID-01: make `spm-cache.lock` describe the host project's *current* resolved graph
after every non-fast-path run, without costing a single byte of enrichment metadata.

Purpose: `installer.rb`'s `generate_lockfile_from_resolved` early-returns whenever the lock
exists, so every package's `version`/`revision` has been frozen at first creation forever. The
umbrella is generated from that lock, a held revision becomes an exact commit pin, and
`swift package resolve` materializes checkouts at that stale commit. Plan 02 proved the slice
end to end for one drifted package; this plan adds membership (drop and add), the preservation
guarantees, and safe degradation — the three places where a naive implementation silently
destroys a working project.

Output: a reconciler that satisfies ROADMAP success criteria 1 and 2, with the highest
regression risk (local/path packages, which `Package.resolved` never lists) covered by a named
example.
</objective>

## Decision IDs

Decision IDs D-01 … D-17 are defined in the `## Decision ID Map` of `06-01-PLAN.md`. This plan
implements D-01, D-02, D-03, D-04, D-05 and D-16.

**Recorded refinement of D-02.** D-02 reads "added with an empty `products[]`, leaving existing
enrichment to populate products later." Research measured that the `products` key must be
**omitted entirely**, not written as `[]`: `installer.rb`'s enrichment loop guards with
`next if pkg_data["products"]`, and `[]` is truthy in Ruby, so a present-but-empty key
suppresses enrichment forever. Omitting the key is what realizes D-02's stated purpose
("leaving existing enrichment to populate products later"); writing `[]` would defeat it.
`Lockfile::Pkg#to_h` already omits the key when products are empty, and `06-VALIDATION.md`
names the covering example "adds a new package without a products key". Implement the omission.

Harden `reconcile_lockfile_from_host_graph` on the four axes that turn a correct refresh into
a destructive one.

**Untouched keys (D-05, ROADMAP success criterion 2).** Assign only `version`, `revision`, and
the membership of the `packages` array. Every other key on a surviving package hash — `products`,
`repositoryURL`, `path_from_root`, `path`, `name`, `branch` — is left exactly as loaded. Never
rewrite an identity field to the host's spelling: the ssh/https equivalence specs treat those
variants as the same package, and rewriting would break them. Never assign
`proj_data["dependencies"]`, `proj_data["platforms"]`, or `proj_data["spm_cache_version"]`.
Reconcile only `@lockfile.projects[File.basename(@project_path)]`; leave every other top-level
project key and every unrecognized key in the project object alone.

**Revision is never cleared.** Assign `pkg["revision"]` only when the live entry supplies a
non-nil revision. A transitive-only package whose revision is nilled out is skipped entirely by
`UmbrellaGenerator`, which silently removes it from the umbrella — the inverse of the bug this
phase exists to fix.

**Unreadable or missing host graph (D-04).** Locate via `Core::PackageResolved.locate(@project_path)`.
When that is `nil`, or when `Core::PackageResolved.pins_or_nil(<path>)` is `nil`, emit exactly
one `Core::UI.warn` naming the path (or its absence) and return without touching the lock.
Do NOT call `@lockfile.save` on that branch. An empty-but-readable pins array (`[]`) is a
different case and is NOT a degradation path — it means the host really resolves nothing from
source control, and the pbxproj union still supplies local refs. Keep the two distinguishable.
Match `command/init.rb`'s warn-and-degrade tone; wording is discretionary (D-17).

**Write gating (D-03).** Keep the `@diff && !@diff.empty?` self-gate from Plan 02, and make
`@lockfile.save` reachable only after at least one mutation has been decided, so an empty diff
or a degraded run leaves the file's bytes untouched.

early-returns when `@lockfile` is nil or when the lock has no entry for
`File.basename(@project_path)` — a renamed project, a hand-written lock, or a lock written for a
workspace — so relying on its save silently loses reconciliation on exactly the projects whose
locks are most likely stale.

Add at most one WHY comment on the revision-never-cleared branch, recording the umbrella-skip
consequence. Do not comment what the code does.
