- [ ] CONSTRAINT: SSE-status falsification — the milestone research's "failed connects answer 503 + `Retry:`, never 204" guidance is FALSE. WHATWG §9.2.3 (fetched verbatim during 14-RESEARCH): ANY non-200 status permanently fails the EventSource connection; an HTTP `Retry:` header plays no role (only the in-stream `retry:` field does). The endpoint ALWAYS answers 200 `text/event-stream`; auth failure (401/403) is deliberately terminal (client shows the locked 13 token-invalid page, never a reconnect promise). Any wave-3 / Phase-15/16 code or spec echoing "503" for the stream is a defect.
- [ ] CONSTRAINT: Asset-path referencing (the G-13-1 class) — Phase 13 SHIPPED with all three dashboard assets 404ing because index.html used bare-relative refs while the router serves only `/assets/*`; 119 green examples missed it because the integration spec re-prefixed refs test-side. Structural mitigation now in the suite: every asset ref is resolved with browser semantics (URI.join against the document origin). Any NEW asset in 14-05 or Phases 15/16 (e.g. a new JS module or image) MUST be referenced as `assets/<name>` and covered by a browser-resolution spec row.

**Do not proceed until both boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Test-side URL rewriting | Specs that re-prefix asset refs (`get("/assets/#{ref}")`) hide real-browser 404s — shipped a blocker past 119 green examples | blocking | web_integration_spec resolves every scanned ref via document-origin URI.join; web_frontend_spec pins relative-only refs — do not weaken either |
| Forever-looping SSE body proc | WEBrick's accept loop joins connection threads (server.rb:210); a proc that never returns hangs `server.shutdown` and breaks WEB-03 exit-0 | blocking | ShutdownSentinel ends every client loop (wave 1); integration spec asserts shutdown-with-open-stream < 10s — any new stream loop must honor the sentinel |
| STATE.md prose drift | gsd-tools owns STATE frontmatter, nothing owns the body (legacy schema); body/table silently lag disk; `state.record-session` also rewrites the file concurrently mid-edit | advisory | After every tool-driven state change, re-read and hand-sync the body; expect the "stale file hash" edit warning |
| Bundler processes via `hub op:start` | hub-spawned processes lack the custom GEM_HOME (~/.xcframework-cli) — bundler dies exit 7 even with env forwarded | advisory | Launch bundler-dependent processes from the bash tool's own session: `cd <cwd> && BUNDLE_GEMFILE=<repo>/Gemfile nohup bundle exec ruby <script> & disown`; readiness = marker file exists |
| OMP agent mid-write death | gsd-* agents can die (exit 1) right after "Writing <doc>" with the artifact complete on disk | advisory | Verify artifacts by CONTENT on disk (sections, byte count, no sentinel) before re-spawning; check `history://<id>` for the composed doc first |
