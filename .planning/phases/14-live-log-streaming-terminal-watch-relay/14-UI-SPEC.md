# Phase 14 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled CSS, zero build step, zero CDN (locked decision, 13-CONTEXT). Phase 14 EXTENDS the shipped Phase 13 system — every token below already exists in `styles.css :root`; nothing is redefined |
| Preset | not applicable |
| Component library | none — vanilla ES modules, no framework. Phase 14 adds exactly ONE second module `assets/log.js` beside `app.js` (explicitly permitted by 14-CONTEXT's LOC-budget note; research Pattern 6) |
| Icon library | none — text glyphs only. Inherited from 13: `✓` / `!` / `✗` (doctor verdicts), `↳` (fix hints), `◆` (macro). Added by this phase: `●` (live/running/connected), `↻` (reconnecting) |

Shipped files this contract extends: `index.html` (gains a fourth panel + the `assets/log.js` module tag), `styles.css` (gains log-section rules on the existing token sheet), `app.js` (untouched — a separate module keeps the dashboard's and the stream's failure domains separate; a stream bug must never take down the state table).

## UI Considerations

Applicable state considerations resolved: 31 covered (explicit), 0 backstop, 0 unresolved — plus 6 dismissed with reasons (categories impossible by construction) — probe-run 2026-09-01 via ui-consideration-probe.cjs over elements E1–E7 (log stream viewport, identity card, anchor chip rail, connection pill + runs dropdown, follow/filter pills, failure banner, in-stream notices); every covered category resolves to a contract line below.

### Layout contract

Single page, no routing (unchanged). The 1280px content column now stacks FOUR panels in this order — 1. Run Log, 2. Cache State, 3. Doctor, 4. Dependency Graph — with `md` gaps and identical panel chrome (`#161B22`, 1px `#30363D` border, 8px radius, `md` padding; header row: title left, controls right).

The Run Log panel body, top to bottom:

1. **Identity card** (D-06) — full width, `sm` padding, 1px border, 8px radius. Three rows:
   - row 1: status glyph+word · trigger badge · command (mono, weight 600) · `Config {config}`
   - row 2 (mono, muted, Label size): `Started {MMM d, HH:MM}` — plus ` · completed {relative}` when the run is finished ({relative} carries its own ago phrasing per the copy table)
   - row 3 (mono, muted, Label size): `spm-cache {argv joined by spaces}` (` · credentials redacted` appended when the header says so), and the run id, each ellipsized on one line with a `title` tooltip
2. `xl` (32px) section break.
3. **Stream group**, stacked with `sm` gaps: failure banner (when present: full-width bar, fail 10%-alpha fill, `✗` glyph, banner text + `Jump to first error` button) · switch-notice bar (when present: muted text, `{run-id}` in the accent control style) · the stream row.
4. **Stream row**: stream viewport (flex: 1, fixed 480px height, `#0D1117` fill, inner vertical scroll, `pre-wrap` Label-mono lines) + anchor rail (fixed 200px, viewport height, own inner scroll, `sm` gap, group labels `Phases` / `Packages`, chips stacked vertically).
5. **Overlay**: one pill row inside the viewport's bottom edge, centered, `xs` inset — the follow-tail pill and the filter pill sit side by side (`sm` gap) when both are present.

Panel header: `Run Log` title left; right side: connection pill, then the `Recent runs` label + dropdown select. No Refresh button, no timestamp stamp — the connection pill IS the panel's liveness marker.

### Interaction contract

- **Stream connect:** `new EventSource('/api/events?token=' + token)` from the sessionStorage token (query-param token = locked 13 posture; EventSource cannot send headers). Pill states per the copy table; `onerror` with `readyState === EventSource.CLOSED` is permanent → the token-invalid page replacement.
- **Cold load (D-13):** three branches — live run (newest file, header pid alive, no `run_end`): card `● running`, replay byte 0, follow on completion. No live run, runs dir non-empty: newest run overall replayed, follow off, card carries the end state + `completed {relative} ago`. Runs dir empty: the `No runs yet` state with only the connection pill live — and when a run then starts, the stream switches INTO it via the normal switch path.
- **Follow/pause (D-01):** follow pins the viewport to the newest line on every append; ANY upward scroll disengages; the pill appears once ≥ 1 line has queued, `{N}` incrementing live; activating the pill re-engages, clears `{N}`, removes the pill. Chip jumps and jump-to-error disengage follow identically — the pill shows only when new lines are genuinely pending. During initial replay, follow engages at completion; the pause pill is a live-tail affordance only.
- **Ring (D-02):** the DOM holds the newest 500 line elements of the displayed run; eviction updates the head notice `{N}` counter; the full run always remains on disk and reload replays it.
- **Anchors (D-07–D-09):** chips render as their anchor events arrive; package chips dedupe by name (first position wins). Chip click = jump to the anchor's divider line + set the filter: a package filter matches its segment (`package_start` through its `package_end`, inclusive); a phase filter matches from the marker to the line before the next phase marker or `package_start`; lines before the first anchor dim under any filter. Filtering DIMS (`--c-muted`), never hides — line positions stay stable, which is what makes D-10's real-position jump possible. The active chip renders in the accent badge style with `aria-pressed="true"`; clicking the active chip clears the filter (view stays put).
- **Failure (D-03/D-10):** non-zero `run_end` → banner + `✗ failed` card flip; CP14 (pid dead, no exit line) → interrupt banner + `! interrupted — exit unknown`. The banner pierces filters; `Jump to first error` exits the filter, then jumps. The banner has NO dismiss control — it belongs to the displayed run and is replaced only by viewing a different run.
- **Auto-switch (D-04):** a new run's arrival switches the stream UNCONDITIONALLY (locked decision — even mid-read of an older run): fresh replay from byte 0, follow on, filter cleared, banner re-derived for the new run, switch notice naming the immediately-previous run.
- **Recent-runs dropdown (D-12):** each open re-fetches `/api/runs` — statuses freshly derived per CP10, never cached. Selecting an entry loads that run in place from byte 0 (research Open Question 1 recommendation: `?run=` replay reusing the id-validation machinery); a live selection follows, a finished selection replays with follow off.
- **Structured events in-stream:** `package_start` and `phase` render as `── {name} ──` divider lines (muted, mono) — these dividers are the jump targets. `run_start`, `run_end`, `package_end`, and `sh` events render NO line (the card, banner, and dividers are their surfaces). Unknown event keys are ignored (forward-compatible; T-12-01: only known keys drive behavior).
- **Body lines:** `stream: "err"` renders the `✗ ` prefix + verbatim text in `:fail`; `stream: "out"` renders verbatim in primary text. Log text renders exactly as captured (Phase 12 transform-free stance) — ANSI escape sequences in captured text render as the literal characters via `textContent`; no ANSI interpretation.
- **No polling:** the log panel never polls; the state table's 5s auto-poll continues independently in `app.js` — a dead stream must not take the table down, and vice versa.

### Accessibility contract

- The panel is a `<section>` with an `<h2>`; every control is a native `<button>` or `<select>` — DOM-order tabbing, Enter/Space activation, no roving tabindex, no ARIA-reinvented widgets.
- `:focus-visible` renders the accent ring on every control (the established `.btn:focus-visible` pattern, extended to chips, pills, and the select).
- Stream viewport: `role="log"`, `aria-live="off"`, `aria-label="Run output"`, `tabindex="0"` — keyboard-scrollable without announcing every appended line.
- Identity card status container: `aria-live="polite"` (the ✓/✗/! flip announces). Connection pill: `aria-live="polite"`. Failure banner: `role="alert"`.
- Active chip carries `aria-pressed="true"`; pill accessible names are their full visible labels.
- No color-only encoding anywhere: every status color pairs a glyph (`✓` `!` `✗` `●` `↻`) and, in the card, a word. All pinned color/text pairs meet 4.5:1 contrast on their fills (existing vocabulary, unchanged values).

## Prohibitions (must-NOT — checker and verifier test these)

1. **No framework, build step, npm dependency, or CDN. No scheme-absolute URLs.** Any new asset MUST be referenced as `assets/<name>` so it resolves through the router's `/assets/*` arm — Phase 13's ship-blocking G-13-1 was exactly a bare-relative asset ref that 404'd in real browsers. The only expected new asset is `assets/log.js`.
2. **No innerHTML, insertAdjacentHTML, document.write, or outerHTML.** Every dynamic string — package names, log text, run ids, argv, notice messages — renders through `el()`/`textContent` (T-13-13). Run text is untrusted subprocess output.
3. **No color-only status encoding.** Every status color pairs with a glyph and, in the card, a word.
4. **No animation of the stream beyond scrolling.** No pulses, transitions, spinners, or smooth-scroll; follow and jumps set scroll position instantly.
5. **No client clock in any stamp.** Relative times compute from server timestamps (hello / `generated_at`), never `Date.now()` (T-13-16).
