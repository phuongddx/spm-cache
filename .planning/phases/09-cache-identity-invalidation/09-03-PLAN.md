<objective>
Empirically verify RESEARCH.md's Assumption A1 (MEDIUM confidence, unresolved by research): does
Xcode's incremental build system reliably notice an in-place-overwritten local `path:`-declared
`binaryTarget`'s content change and re-link, without spm-cache needing to touch DerivedData
itself? CONTEXT.md's locked decision (D-11) is that spm-cache does NOT proactively purge
DerivedData -- this plan proves that decision is safe against the real reference project rather
than leaving it an untested assumption (ROADMAP.md success criterion 5).

of whether a correct miss-then-rebuild actually reaches the compiled app, or whether Xcode's own
incremental build silently keeps linking the stale, previously-cached content despite the
xcframework on disk having genuinely changed. This requires a human with Xcode and the real
external reference project -- not reproducible by an autonomous agent in this environment.

outcome and any follow-up this phase's success criteria require.
