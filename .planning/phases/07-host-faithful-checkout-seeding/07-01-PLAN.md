<objective>
Every per-package build resolves its transitive dependencies from the host app's resolved graph, not
from that package's own manifest ranges (FID-02): before the first `swift package describe` call,
`BuildPipeline.run` seeds the checkout with the host's `Package.resolved`, verbatim, atomically, with
restore-on-failure. Vendored-`.xcodeproj` packages -- for which this is structurally a no-op -- are
classified before seeding and reported as an explicit *not-graph-pinned* category rather than silently
counted as pinned (FID-05). With no host graph available, behavior is byte-for-byte identical to today.

Purpose: this is the phase's correctness mechanism -- the actual fix for the milestone's
worse-than-stated failure (ARCHITECTURE.md §1: isolated builds resolve fresh from open manifest ranges,
not a stale pin, i.e. unbounded upward drift; VERIFIED swift-argument-parser 1.2.0 -> 1.8.2, exit 0).
Output: `SPM::ResolvedGraph`, wired into `BuildPipeline.run` and `Installer::Build`, both hermetically
tested.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host `Package.resolved` -> checkout | Project-controlled file (not spm-cache-generated) copied verbatim into a package checkout on disk |
| Checkout classification -> seed/skip decision | A filesystem shape (presence of `*.xcodeproj`) gates whether a checkout is written to at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering | ResolvedGraph.seed! write destination | medium | mitigate | Destination path is always `File.join(pkg_dir, "Package.resolved")` -- no untrusted content ever interpolates into the destination path; `pkg_dir` itself already comes from `checkout_map`'s basename-only slugs (existing mitigation, not weakened here) |
| T-07-02 | Tampering | ResolvedGraph.seed! mid-write crash | high | mitigate | Temp-file-then-rename atomic write (D-05) -- a crash mid-copy can never leave a half-written `Package.resolved` in the checkout |
| T-07-03 | Tampering | Stale seeded file after an aborted/interrupted build | medium | mitigate | success-flag + ensure -> restore! on any non-success exit (StandardError or Interrupt), so a later unrelated build of the same checkout never inherits a synthetic file from a failed run |
| T-07-04 | Information Disclosure | Seeded Package.resolved reveals dependency URLs/versions inside vendored checkouts | low | accept | These are already-public repo URLs already present in the host project; no new secret exposure |
| T-07-05 | Integrity (misclassification) | vendored_xcodeproj? false positive silently skips seeding an actually SPM-native package, defeating FID-02 with no error | high | mitigate | Exact same glob shape as the existing, field-proven `Buildable#ambiguous_project_checkout?` precedent; explicit UI report line makes every skip decision auditable, not silent |

</threat_model>
