# Plan 16-03 — The one server-side derivation: toggleable, why not, and saved vs applied

<planning_context>
phase: 16 — Package Toggles + Panel Completion
mode: standard (expansion — the read model's half of TOGL-02 and all of TOGL-03, on the fresh-read seam 16-01 opened)
sources: 16-CONTEXT.md D-06, D-09; 16-RESEARCH.md §Q3 (applied truth = graph status, saved truth = exact entry, the divergence definition, the fresh-read recommendation), §Q4 (the five-reason fact table with the precedence recommendation and the fidelity-gate recommendation), Pitfalls 5 and 8, Assumptions A3/A4; 16-UI-SPEC.md A1/A2 (field names planner-discretionary, rendering verbatim, unknown values neutral) and the Interaction contract's saved-vs-applied bullet; 16-VALIDATION.md the Wave-2 state row; ROADMAP Phase 16 SC2-SC3; REQUIREMENTS TOGL-02, TOGL-03
planner decisions recorded here: reason precedence is excluded → plugin → binary-target → pattern-managed → fidelity (16-RESEARCH's recommendation, taken); the fidelity gate is the warn status only, with the neutral not-graph-pinned status staying toggleable (A4, taken); pending is narrowed to toggleable rows (the planner's own correctness call — see the truths).
recorded limitations (accepted, in scope by D-01, and to be restated in this plan's SUMMARY so 16-06 does not report them as defects): (a) the table's row universe is UNCHANGED — it is the cache inventory, so a package that has never been cached has no row and therefore cannot be switched back on from the browser; the CLI verb remains its path, and widening the row set is a table-contract change outside this phase's boundary. (b) A package cached in both configurations produces TWO rows carrying identical toggle fields; both are honest views of one saved value, and a toggle from either is the same request. (c) Macro-backed packages are not gated: the generator writes the macro flag literally false today (Pitfall 8, Assumption A3), so a `plugin` reason cannot fire for them and they stay toggleable — the gap belongs to the generator, not to this derivation.
</planning_context>

and does its saved state differ from what the last sync actually applied.

WHY" — both of which are, by CP10, single server-side derivations that the client renders without
interpretation.

reason, every precedence collision, the divergence rules and the degradation paths.
</objective>
