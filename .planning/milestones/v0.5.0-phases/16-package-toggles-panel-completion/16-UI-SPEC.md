### Layout contract

Single page, no routing, FOUR panels in the 14 order — Run Log, Cache State, Doctor, Dependency Graph. Phase 16 adds no panel: the toggles live INSIDE the Cache State panel, whose data they mutate.

The Cache State panel body, top to bottom:

1. **Unsaved-changes bar** (`#state-sync-bar`) — first child of the panel body, ABOVE the table, rendered only when at least one row's saved state differs from applied (absent otherwise — the table is the body's first child again, 13 geometry restored). Flex row mirroring `.build-confirm`: warn 10%-alpha fill, `xs`/`sm` padding, 4px radius, `sm` gaps, `sm` margin below, wraps on narrow viewports. Children in DOM order: bar text (Body size, primary, flexes) · `Revert all` (`.btn-quiet`) · `Apply now` (`.btn` accent) · message slot (`#sync-message`, reusing `.ctl-message` / `.ctl-error` verbatim — `margin-left: auto`, muted Label size, `.ctl-error` flips it to fail Body size).
2. **The state table** — unchanged 13 chrome (full width, fixed layout, `sm` cells, ellipsizing) with a SIXTH column appended:

| Column | Header | Width | Content |
|--------|--------|-------|---------|
| 1 | `Package` | 36% | unchanged (`◆ ` macro prefix, ellipsis + `title`) |
| 2 | `Config` | 12% | unchanged |
| 3 | `Size` | 10% | unchanged (mono) |
| 4 | `State` | 12% | unchanged — the APPLIED cache outcome (hit/missed/ignored/excluded/plugin badge) |
| 5 | `Fidelity` | 18% | unchanged (mono) |
| 6 | `Cached` | 12% | the toggle cell (anatomy below) |

Toggle-cell anatomy, in DOM order, all in one nowrap/ellipsis cell: the native `<input type="checkbox">` (checked = the SAVED config says cached; `class` none, `accent-color: var(--c-accent)`, `:disabled` at the sheet's 0.6 opacity posture) · the reason chip (`.badge` + the mapped class, ONLY on disabled rows) · the `pending` chip (`.badge-neutral`, ONLY on rows where saved ≠ applied). Reason + pending chips co-render space-separated when both apply.

### Interaction contract

All POSTs ride the SAME per-launch token via the `X-SPM-Token` header (D-04 posture — custom headers only; never query-param, never body, never logs). Envelope shape `{status, data}` as the GETs; 401/403 renders the locked token-invalid page (shared). Working endpoint paths per 16-CONTEXT's discretion (exact paths planner-discretionary; the CONTRACT is method, body, and semantics): `POST /api/toggle` with JSON body `{"package": "<raw name>", "cached": <bool>}` — single package per request, instant config write, NOT slot-gated (D-08: toggling stays available during runs); `POST /api/apply` with an empty JSON body — spawns `spm-cache use` through `Web::Jobs` (trigger `ui`, same single-slot 409 semantics, same stream view; D-07); `POST /api/revert` with an empty JSON body — batch config write restoring saved:=applied for every diverging row, NOT slot-gated (A3). The merge algorithm behind the writes (key-level vs list-level) is 16-CONTEXT discretion; the UI never models it — it renders only polled server truth.

- **Saved vs applied (D-06):** the checkbox ALWAYS reflects the SAVED ignore list on disk; the `State` cell continues to show the APPLIED outcome from the last sync. A row is pending when saved ≠ applied — the `pending` chip marks it and the bar exists while ANY row is pending. Both truths arrive per-row from `/api/state` (read-model extension; field naming planner-discretionary) — the client computes nothing but `saved !== applied` per row and "any row diverges" for the bar.
- **Toggle click/keyboard change:** fires `POST /api/toggle` with the checkbox's NEW value immediately (D-08 instant persist). NO busy state, NO per-row disable — the control stays live; a rapid second flip is a legitimate second POST, and the locked merge-write (D-04) makes concurrent writes safe. **Poll integrity:** while any toggle POST is in flight, the 5s poll SKIPS the table redraw (stamp included — the stamp never claims data newer than what is shown); the next cycle renders persisted truth. This kills the visual bounce of a checkbox snapping back for up to one poll.
- **Reasons (D-09):** the client NEVER derives a reason — the read model serves `toggleable: false` + `reason` per row (CP10: one server-side derivation); the UI renders the disabled checkbox + chip verbatim. There is no toggle path for a disabled checkbox; pattern-managed rows are never editable from the UI (the yml editor is out of scope by REQUIREMENTS).
- **Bar appearance:** derived from the freshest `/api/state` — present when ≥1 row diverges, absent at zero. No focus is stolen when it appears; `aria-live="polite"` on the bar announces the appearance. Every connected tab converges identically via its own poll — no cross-tab messaging, no new channel (A6).
- **Apply now click:** the button disables instantly (double-submit guard) → POST → 2xx: message `Applying…` (muted), button stays disabled while the spawned run holds the slot; the run appears in the Run Log panel via the existing auto-switch path with the `ui` badge — zero new streaming plumbing. 409: the amended busy message in the bar's message slot (fail), button re-enables. Network/HTTP error: the apply-failure template (fail), button re-enables. Re-enable on success: the `spm-run-progress` `ended` milestone (15's A10 event) — and the bar itself disappears when a poll shows convergence (saved == applied), which is the authoritative exit; a missed event is backstopped by the poll, reload is always truth (A7).
- **Slot-sharing amendment (A5):** the single spawn slot now governs Build, Rebuild all, Rollback, AND Apply now. While ANY of them is in flight, all FOUR controls disable (15's freeze set extends by one button); the `ended` milestone re-enables. The Run Log row's message machinery is untouched — the apply run's progress renders in the bar, the run's output in the stream.
- **Revert all click:** both bar buttons disable instantly (double-submit guard) → POST → 2xx: message clears, buttons re-enable, the bar REMAINS until a poll shows zero diverging rows (≤ one poll cycle of honest lag — the client never pre-announces convergence). 409: not a revert path (not slot-gated); error: the revert-failure template in the message slot.
- **Toggle save failure:** the pinned `Couldn't save the toggle for {package}…` line renders fail-colored directly above the table. It SURVIVES poll re-renders (a rejected click never silently vanishes) and is cleared by the next successful mutation (any toggle/apply/revert) or the panel's `Refresh` button. The checkbox continues to show server truth — the unchanged value is part of the story, never a silent swallow.
- **No dialogs anywhere:** apply, revert, and toggle are all inline, one-surface actions; no `alert()`, no `confirm()`, no `prompt()` — the dashboard has none (15 prohibition 3 stands).

### Accessibility contract

- The toggle is a native `<input type="checkbox">` (D-02 — keyboard operable, no ARIA-reinvented switch, no `role="switch"`): Space toggles, DOM-order tabbing (row order), no roving tabindex. Each input carries `aria-label="Toggle caching for {package}"`.
- `:focus-visible` renders the 2px accent outline ring on checkboxes and bar buttons (the established `.btn:focus-visible` pattern, extended to the checkbox).
- Disabled checkboxes are native `disabled`; the reason chip in the same cell is the visible, announced WHY (DOM order delivers chip text after the control). No color-only encoding: reasons and pending are WORDS; the bar's warn fill pairs with a full-sentence text.
- The bar is `role="group"` + `aria-label="Unsaved changes"` with `aria-live="polite"` (appearance announces; disappearance removes the node and announces nothing). The message slot is `aria-live="polite"`; the `#sync-message` span swaps via `hidden` so idle state never announces.
- The bar never steals focus; `Apply now` and `Revert all` are native buttons — Enter/Space activation, `.btn-quiet` before `.btn` in tab order (quiet-left, primary-right, the 15 confirm-bar order).

## Prohibitions (must-NOT — checker and verifier test these)

1. **No new files, no new assets, no framework, no build step, no CDN, no scheme-absolute URLs.** All changes land in the existing `styles.css` / `app.js`. `index.html` and `log.js` are untouched. The G-13-1 asset-ref class cannot recur — nothing new is referenced.
2. **No innerHTML, insertAdjacentHTML, document.write, or outerHTML.** Every new dynamic string — package names, reason strings, envelope `{message}` values — renders through `el()`/`textContent`. Envelope messages are server-authored and treated as untrusted.
3. **No native dialogs.** No alert(), no confirm(), no prompt() — toggle, apply, and revert are inline one-surface actions; `Revert all` gets no confirm (see Copywriting Contract).
4. **No new polling channel, no new timer, no second EventSource.** Bar visibility, chips, and convergence derive from the existing `/api/state` poll plus the `spm-run-progress` CustomEvent only. The state table's 5s poll remains the page's only timer.
5. **No client clock.** The toggle surface renders no timestamps; nothing here may call `Date.now()` (T-13-16 stands).
6. **No ARIA-reinvented switch.** The toggle is a native `<input type="checkbox">` — no `role="switch"`, no styled-div toggle, no animation of the control.
7. **No second mutation token, no query-param token on POSTs** (D-04: same per-launch token, `X-SPM-Token` header only).
8. **No bulk toggle controls and no per-row Apply.** No master checkbox, no multi-select, no per-row apply button — D-06 pins exactly ONE `Apply now`, bar-level; bulk operations are outside the phase boundary.
9. **No client-side reason derivation.** The UI never computes pattern matches, plugin status, or fidelity gates — reasons arrive per-row from the read model and render verbatim (CP10). Unknown reasons render verbatim-neutral, never filtered, never mapped to guessed copy.
10. **No editing of ignore-list patterns from the UI.** `pattern-managed` rows are read-only; a general yml editor is out of scope by REQUIREMENTS.
11. **No display of raw server 409 reasons or envelope internals** — the busy/error copy is client-pinned; only the pinned failure templates interpolate the envelope `message`.
12. **No silent states.** A disabled checkbox always has its reason chip; a rejected toggle always renders its fail line (surviving polls); a held slot always explains itself in the bar's message slot.
13. **No optimistic applied-state claims.** The UI never marks a change "applied" before a poll shows convergence — the bar and `pending` chips clear on server truth only, never on POST success alone.
