<objective>
Make lock contention visible in the run log itself: at both blocking flock sites, a run that
must wait first announces itself with one stdout line — 'Waiting for build lock…' — which the
Phase 12 tee captures into the blocked run's JSONL, so the SSE stream (14-01) renders the
attribution inline exactly as terminal users see it, with zero new logging machinery.

Purpose: SC4's lock-held attribution half (LOGS-05) and CP10's derive-from-the-run discipline —
the blocked run testifies about itself; the server never guesses.

Output: two small Installer edits (identical three-step shape), one new spec file, no API or
frontend changes.
</objective>
