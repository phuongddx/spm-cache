<fix_decision>
**Chosen: MJ-01 Option A on ALL matrix legs** (not Option B, not Option A-on-one-leg). This is an engineering judgment call within the gap's stated options; rationale recorded here so the executor does not relitigate it:

- **Why A over B:** Option B (running the six `spec/gen_proxy_*_spec.rb` files inside `swift-tests`) hardcodes a filename list in the workflow — every future binary-gated spec file must be remembered and added to that list or it silently re-opens the exact gap on the Ruby legs (coverage hole by default). It also splits suite reporting across jobs, and the Ruby legs would still print `23 pending` summary noise. Option A keeps one unfiltered `bundle exec rspec` invocation per leg: any spec that lands in `spec/` runs in CI by default.
- **Why all legs, not `if: matrix.ruby == '3.3'` only:** the repo is public (Homebrew + RubyGems distribution), so macOS runner minutes are free — the cheapest-cash argument for a single-leg build does not apply. Uniform legs mean every leg's summary line is an equal full-suite attestation, with no "authoritative leg" asymmetry to document. Cost is one ~1–2 min `swift build -c release` per leg.
- **Why Xcode selection is added too (not relying on the runner default):** `tools/spm-cache-proxy/Package.swift` declares `swift-tools-version:6.0`; the macos-15 image's default Xcode drifts over time. Pinning via the identical `maxim-lobanov/setup-xcode@v1` + `xcode-version: '16'` step already proven green in `swift-tests` makes the build deterministic and matches RESEARCH.md's own gotcha ("pin Xcode explicitly … to avoid silent drift") and 01-PATTERNS.md ("Must add maxim-lobanov/setup-xcode@v1 with xcode-version: '16' to ruby-tests if adding the build step").
- **Why the `swift-tests` build step is removed (MI-02):** the gap's missing-items list explicitly directs it once Option A is chosen. `swift test` compiles its own debug artifacts from sources; the release binary was dead work in that job.
- **Why NOT `workflow_dispatch`:** it would not enable pre-merge verification anyway (dispatch requires the trigger to exist on the default branch, and main's ci.yml does not have it), and post-merge the existing `push: branches: [main]` trigger already fires.
</fix_decision>
