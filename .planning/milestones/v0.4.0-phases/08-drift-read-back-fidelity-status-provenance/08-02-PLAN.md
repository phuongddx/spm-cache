<objective>
`spm-cache cache list` names each cached package's fidelity status (`host-pinned` /
`resolution-incompatible` / `not-graph-pinned`), read from the `.provenance.json` sidecar
08-01's `BuildPipeline` writes, falling back to `not-graph-pinned` when no sidecar exists. This
closes the `cache list` half of DIAG-02 -- "no package's resolution outcome is unauditable."

The current implementation (`lib/spm_cache/command/cache/list.rb:11-23`) is a bare
`Dir.entries(cache_dir).sort.each { puts "  #{entry}" }` loop with zero per-module concept:
confirmed by RESEARCH.md that it already prints sidecar files (e.g. `.shims.json`) as their own
spurious "package" lines today, a pre-existing bug 08-01's new `.provenance.json` sidecar would
otherwise make worse (one more spurious line per cached package). This plan rebuilds the command
from scratch around `*.xcframework` entries specifically, fixing that bug as part of the same
change.

Purpose: without this, a developer has no way to audit fidelity status for anything already
cached from a prior run -- the drift/status reporting 08-01 built only speaks at build time.
Output: rewritten `Command::Cache::List#run`; `spec/command_cache_list_spec.rb`.
</objective>
