## Fix-shape evaluation — why (C), and what (C) actually costs

Three shapes were available. All three produce the **same located file in every case**, because
`locate(p)` and `locate(p, parent_fallback: true)` return early and identically on tiers 1-3 and
differ **only** when all three miss (`package_resolved.rb:29-45`). The parent tier is therefore the
entire divergence surface, and any fix that closes it accepts the same behavior delta. The choice
is about structure, not about which bytes get read.

**(A) Pass `parent_fallback: true` from the installer's own locate calls — REJECTED.**
It restores agreement today and leaves three independent resolvers in place, so the next site added
to `installer.rb` can silently diverge again exactly as this one did. It also breaks a recorded
acceptance criterion of an already-executed plan: `06-02-PLAN.md:431` requires that
`parent_fallback: true` appear in exactly one of the five collapsed files. (A) puts it in two.
One claim in the gap brief does **not** survive source reading and is not a reason to reject (A):
`installer.rb:156` is the *tolerant* site — it reads `pins_or_nil` at line 166 and warns
(`installer.rb:166-171`). The strict `pins` accessor is at `installer.rb:293`, in
`generate_lockfile_from_resolved`, which is a different call site. (A)'s real cost is structural,
not a new raise surface at the reconciler.

**(B) Remove `parent_fallback: true` from `DiffDetector` — REJECTED.**
It regresses real, pre-Phase-6 behavior. `diff_detector.rb:150-155` legitimately reached
`<parent>/App.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` before this
phase; wave 2 preserved that deliberately and `spec/package_resolved_spec.rb:65` asserts it.
Restoring agreement by making both sides blind to a file one of them correctly found today trades
a convergence bug for a detection bug. Rejected explicitly.

**(C) Resolve once per run and share the answer — CHOSEN.**
The gap's root cause is "two independent resolvers can disagree". (C) removes the second and third
resolvers instead of aligning them. Concretely: `DiffDetector` memoizes its located path and
exposes it; `Installer` keeps the detector it already builds in `detect_diff` and both
installer-side consumers read the path from it. One locate call per run, asserted by a spec, so
divergence cannot be reintroduced without a test failing.

Three costs the gap brief anticipated turned out **not** to apply, verified by reading the tree:

1. **No constructor change is needed.** `DiffDetector.new` appears in `lib/` at exactly two places,
   both in `installer.rb` (`:57` and `:177`) — `core/watcher.rb:120` and `command/use.rb:88` call
   `PackageResolved.locate` directly and never construct a detector. The fix promotes a private
   method and memoizes it; the keyword signature is untouched, so no existing caller or spec is
   affected and no default-nil parameter is required.
2. **The duplicate detector at `installer.rb:177` disappears**, taking with it a redundant
   `Xcodeproj::Project.open` and a redundant lockfile read per run.
3. **Memoizing the detector across `ensure_config_file` is safe.** `Config#load`
   (`config.rb:49-53`) writes only `@config_path` and `@raw`; it never touches `project_dir`, and
   `lockfile_path` is derived from `project_dir` alone (`config.rb:92-94`). The memoized detector
   cannot hold a stale lockfile path. The watch loop builds a fresh `Installer::Use` per iteration
   (`watcher.rb:91`, `command/watch.rb:37`), so a memo never spans two regenerations.

The behavior delta (A) and (C) share, stated plainly rather than hidden: **the installer will now
accept a parent-level `Package.resolved` it previously ignored.** Three properties bound it, all
already in the locator: `sandboxed?` excludes anything under `spm-cache/`, so the hazard research
§Q1 point 3 named — reading spm-cache's own generated `umbrella`/`proxy` resolved files as the host
graph — cannot occur; `exclude_under: project_path` keeps the project's own nested stale copy from
re-entering through the parent; and the parent tier is consulted only after tiers 1-3 all miss, so
no project that works today changes answer.
