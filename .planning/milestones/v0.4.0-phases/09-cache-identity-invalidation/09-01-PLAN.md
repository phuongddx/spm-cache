<objective>
Make `BinariesCache.hit(module:)` (Swift) provenance-aware: a cache hit now requires the
sidecar's recorded pin for a package's identity to agree with the host's current pin, and a
totally-absent sidecar is an unambiguous miss (CACHE-02). Close the one hazard that makes a naive
version of this rule unsafe -- a vendored-`.xcodeproj` (Class E) or no-host-graph package whose
sidecar is currently *deleted* on every build would become a permanent, every-build cache miss --
by making `BuildPipeline.report_fidelity`'s `unless seeded` branch **write** an explicit
`not-graph-pinned` sidecar with empty `pins` instead of removing it.

Purpose: without this plan, Phases 6-8's fidelity fix never reaches an existing user -- the actual
cache-hit decision (`Cache.swift:19-22`) is still a bare `fileExists` check with no identity/version
dimension at all, so a pre-Phase-9 (or cross-project, mismatched) artifact keeps being served
forever.

Output: `hit(module:identity:currentPin:)`'s new signature and sidecar-read logic, the
`report_fidelity` fix, full Swift unit coverage (`CacheTests.swift`), and a real-binary
end-to-end spec (`spec/gen_proxy_provenance_spec.rb`) proving SC1 (no-provenance upgrade miss),
SC2 (partial invalidation), and SC3 (cross-project non-sharing) via the actual compiled CLI.
</objective>

Design decisions this plan makes (not literally spelled out in CONTEXT.md, resolved here from
reading the actual current source this session):

- **`copy_prebuilt_binary_target`'s own early `FileUtils.rm_f("#{output_path}.provenance.json")`
  (build_pipeline.rb, immediately after its `.shims.json` cleanup) is deliberately left
  UNCHANGED, diverging from 09-RESEARCH.md's literal "also touch" suggestion.** Verified this
  session: `BuildPipeline.run` calls `report_fidelity` unconditionally, immediately after
  `perform_build` returns successfully, with no other sidecar-touching statement in between --
  so whatever this early `rm_f` does is always superseded a moment later by `report_fidelity`'s
  own write (real pins if `seeded`, or this plan's new not-graph-pinned write if not). Changing
  it would be a no-op with respect to final on-disk state; leaving it preserves its own
  legitimate purpose (removing a stale sidecar immediately after the artifact bytes are
  overwritten, in case the process crashes in the narrow window before `report_fidelity` runs).
- **The `unless seeded` fix applies to BOTH sub-cases `seed_host_graph` can return `false` for**:
  a vendored-`.xcodeproj` checkout AND a nil `resolved_pins_file` (the `spm-cache pkg build`
  standalone path, and the rare "no host graph anywhere" case inside `Installer::Build`). Both
  share the one `report_fidelity` call site, so both existing spec assertions in
  `spec/build_pipeline_provenance_spec.rb`'s "not-graph-pinned paths" describe block (currently
  asserting "no sidecar is written") must be updated together in Task 2 -- confirmed
  `spm-cache pkg build`'s own `--out` default (current directory) is structurally distinct from
  the shared `~/.spm-cache/<config>/` dir `hit()` reads from, so this is a safe, contained
  change with no scope creep into CACHE-02's actual identity-comparison concern.
- **`hit()`'s new `identity`/`currentPin` parameters are non-optional-required** (no default
  values) since `ProxyGenerator.swift:119` is verified as the SOLE call site in the codebase.
</context>
