# spm-cache v0.3.0 — Design: `watch` + `init` + `doctor`

> **Status:** Approved design (2026-08-10)
> **Direction:** Mixed cycle — one moat feature, one adoption feature, one reliability feature
> **Theme:** *"The only SPM cache that watches your project, sets up in one command, and tells you when something's wrong."*
> **Scope:** v0.3.0. Targets existing REQ-001–016 parity; introduces new capabilities.

---

## Context & Rationale

`spm-cache` (v0.2.8) is a mature shipped tool that caches Swift Package Manager dependencies as `.xcframework` binaries via a proxy-package architecture. The competitive landscape (`competitive-analysis-2026-07.html`, `scipio-deepdive-features-2026-07.html`) shows spm-cache's structural moat over Scipio (544★) and xccache (71★): it reads the Xcode project directly and swaps binaries transparently — no separate manifest, no drag-drop, automatic cache-miss→source fallback.

This v0.3.0 cycle deepens that moat, removes adoption friction, and hardens reliability. Three features, one per pillar, non-overlapping.

### Existing code to build on
- `lib/spm_cache/core/diff_detector.rb` — `DiffDetector` compares `spm-cache.lock` vs live `Package.resolved` + `project.pbxproj`; returns structured `Diff` (added/removed/updated).
- `lib/spm_cache/installer/use.rb` — `Installer::Use#perform_install` already implements the diff-driven fast path (empty diff + materialized proxy = no-op; otherwise full regeneration).
- `lib/spm_cache/core/config.rb` — `Config` Singleton with `DEFAULT_CONFIG`, `spm-cache.yml` load, `project_dir`/`config_path`.
- `lib/spm_cache/core/lockfile.rb` — `Lockfile` + `Pkg` model, seeded from `Package.resolved`.
- `lib/spm_cache/core/sh.rb` — `Core::Sh.run` (Open3) shell-out helper; all external commands route through it.
- `lib/spm_cache/storage/git.rb`, `lib/spm_cache/storage/s3.rb` — remote cache backends already implemented.
- `.github/workflows/update-tap.yml` — release-only Homebrew tap updater (the ONLY CI workflow today; no test pipeline).

## Feature 1 (Moat): `spm-cache watch` — Auto-Sync on Project Change

### Goal
A long-running mode that auto-regenerates the proxy package whenever the Xcode project's SPM graph changes. The visible, "wow" packaging of the structural moat: the Xcode project is the single source of truth — no separate manifest, no manual re-run.

### Why this is the moat
Scipio requires a hand-written separate `Package.swift` manifest (`F6` sync nightmare). xccache shares the proxy-package architecture but ships no auto-sync. `watch` turns the existing `DiffDetector` + fast path into a zero-touch loop — something neither competitor can match without reading the live Xcode project the way spm-cache already does.

### Architecture
`watch` wraps `Installer::Use#perform_install` in a debounced filesystem-watch loop. It does **not** replace `use`; it is `use` on autopilot.

### Components
- **`Command::Watch < Command`** (`lib/spm_cache/command/watch.rb`) — new subcommand.
  - Options: `--project` (default `.`), `--debounce SECONDS` (default `2`), `--once` (single sync-and-exit; for CI/testing).
  - Honors the inherited `--sdk` / `--config` / `--log-dir` base options.
- **`Core::Watcher`** (`lib/spm_cache/core/watcher.rb`) — the watch loop.
  - Binds `FSEvents` via Ruby `Fiddle` (stdlib) to CoreServices — **no new gem dependency**. spm-cache is macOS-only already; the native API is the right call.
  - Watches **only** `Package.resolved` and `project.pbxproj` inside the `.xcodeproj` bundle (NOT the whole bundle — Xcode rewrites many files constantly, producing noise).
  - Debounces: collapses burst saves (Xcode writes `project.pbxproj` in a resolve+write+sign flurry when adding a package) into one regeneration.
  - Invokes `Installer::Use` regeneration path on a non-empty diff; logs "no change" on empty diff; loops.

### Data flow
```
fs event (Package.resolved | project.pbxproj changed)
  → debounce (default 2s, --debounce configurable)
  → DiffDetector.compare(spm-cache.lock vs live Package.resolved + pbxproj)
  → diff empty?  → log "no change"; continue loop
  → diff present? → Installer::Use regeneration path:
                       sync_lockfile → prepare_proxy → integrate_proxy_into_project → gen_cachemap_viz
                 → emit cachemap status (hit / miss / changed)
  → loop
```

### Error handling
- **Continue-on-error loop:** a transient regeneration failure (e.g. proxy resolve hiccups) is logged with a timestamp and the loop **continues**. A build failure must not kill the watcher.
- **Fatal exits (non-zero):** project file deleted/moved, `.xcodeproj` unwatchable, or `Installer` construction fails (bad project path).
- **Interruption:** `SIGINT`/`SIGTERM` → flush any pending debounced event, log "watch stopped", exit 0.

### Testing
- `--once` runs a single sync-and-exit → unit-testable without the OS filesystem API.
- The watcher loop is tested via a fake-clock + injected event source. The OS `FSEvents` API itself is not unit-tested (it's the platform boundary).
- Spec: `spec/watch_spec.rb` — covers `--once` path, debounce collapse, continue-on-error, and fatal-exit cases.

### Decisions locked
- **Watcher mechanism:** native `FSEvents` via `Fiddle` (zero new gem). ~80-line binding.
- **Watched files:** `Package.resolved` + `project.pbxproj` only.
- **Loop semantics:** continue-on-error; fatal exits for missing/unwatchable project.

> **Deviation note (2026-08-24):** the "Watcher mechanism" decision above was superseded during implementation — `watch` shipped with stdlib mtime+size polling, not a native binding (user-accepted 2026-08-24; see `.planning/phases/05-auto-sync-watcher/05-CONTEXT.md` and the ROADMAP criterion-5 amendment). The historical body is otherwise unchanged.

## Feature 2 (Adoption): `spm-cache init` + GitHub Action

### Goal
Compress the entire first-run journey into two commands: `init` to bootstrap a project, and the Action to cache in CI. Removes the cold-start friction that keeps teams on Scipio.

### 2a. `spm-cache init` wizard

#### Components
- **`Command::Init < Command`** (`lib/spm_cache/command/init.rb`) — interactive wizard. Non-interactive via flags (`--platform ios,macos --config debug --remote git --remote-url … --branch main` for scripting/CI).
- Reuses `Core::Config` to write `spm-cache.yml` and `Core::Lockfile` to seed `spm-cache.lock`.
- Auto-detects `.xcodeproj` in `cwd` (or `--project`) → reads `Package.resolved` to pre-populate the lockfile so the first `use` hits the fast path.

#### Wizard flow
```
detect .xcodeproj in cwd (or --project)
  → prompt: platforms (iOS / macOS / watchOS / tvOS)  [multi-select]
  → prompt: default config (debug / release)
  → prompt: remote backend (none / git / s3)
       git → remote URL + branch
       s3  → bucket URI + creds file path
  → generate spm-cache.yml (diff-merge over DEFAULT_CONFIG)
  → generate spm-cache.lock from Package.resolved
  → append "spm-cache/" sandbox to .gitignore (idempotent — no duplicate lines)
  → print "Next: run `spm-cache build <target>` then `spm-cache use`"
```

#### Idempotency (locked decision)
Re-running `init` on a project with an existing `spm-cache.yml` performs a **diff-merge**: preserves user keys, adds any new defaults, never overwrites. Mirrors the philosophy of `use`'s diff handling and prevents data loss. Tradeoff: slightly more complex than a blind overwrite — worth it.

### 2b. GitHub Action (`phuongddx/spm-cache-action`)

#### Separate repo, thin wrapper
The Action lives in its **own repository** (GitHub's `uses:` resolution requires this). It is a thin composite/JS wrapper that shells out to the installed gem — it does **not** reimplement logic. ~50 lines: `setup-ruby` → `gem install spm-cache` (or `bundle`) → run the requested command.

#### Workflow shape
```yaml
- uses: phuongddx/spm-cache-action@v1
  with:
    command: pull          # or push / sync
    backend: s3            # or git
    backend-url: ${{ secrets.SPM_CACHE_S3 }}
    config: debug
```

#### Decision locked
- Separate repo (GitHub requirement); real logic stays in the gem.
- Thin shell-out, no logic duplication. Maintenance surface kept minimal.

### Testing
- `spec/init_spec.rb` — runs `init` in a `Dir.mktmpdir` with a fixture `.xcodeproj` skeleton; asserts `spm-cache.yml` contents, lockfile seeded from `Package.resolved`, `.gitignore` updated once, and idempotent re-run preserves user keys.
- The Action is smoke-tested in its own repo's CI (out of scope for the gem's spec suite).

## Feature 3 (Reliability): `spm-cache doctor` + Test CI Pipeline

### 3a. `spm-cache doctor`

#### Goal
Turn "why did my cache break?" into a 2-second command. Diagnoses toolchain drift, cache-dir health, and remote-backend connectivity.

#### Components
- **`Command::Doctor < Command`** (`lib/spm_cache/command/doctor.rb`) — runs checks, prints report. `--json` for machine-readable CI output.
- **`Core::Diagnostics`** (`lib/spm_cache/core/diagnostics.rb`) — a data-driven **check registry**. Each check is an object with `name`, `run` (returns `:ok | :warn | :fail` + message), and `fix_hint`. Data-driven, not hardcoded — so checks can be added/removed via config without touching the command.

#### Initial check set (7)
1. **`xcode_version`** — active `xcodebuild -version`; warn if below a known-good floor.
2. **`swift_version`** — `swift --version`; warn if mismatched with the companion tool's Swift 6.0 requirement.
3. **`toolchain_path`** — `xcrun --find swift`; fail if missing.
4. **`cache_dir_health`** — `~/.spm-cache` size + orphaned binaries (cache dirs with no lockfile entry — a known v0.2.0 rekeying artifact).
5. **`library_evolution_compatibility`** — per-package LE check; surface packages that cannot build with LE enabled.
6. **`remote_backend_connectivity`** — for the configured backend: Git → `git ls-remote`; S3 → `aws s3 ls` with creds. Warn on auth failure.
7. **`companion_binary`** — is `tools/spm-cache-proxy/.build/release/spm-cache-proxy` built and version-compatible with the gem?

#### Output
- Human: color-coded report (green/yellow/red per check), summary line (`5 ok, 2 warnings, 1 failure`), and a `fix_hint` for each non-ok check.
- Machine: `--json` emits the same data as a JSON document for CI hooks and the GitHub Action.

#### Decision locked
Data-driven check registry over hardcoded if/else — future checks added via config, no command edits.

### 3b. Test CI pipeline

#### New workflow
`.github/workflows/ci.yml` (distinct from the existing release-only `update-tap.yml`):
- **Matrix:** Ruby 3.0 / 3.1 / 3.2 / 3.3 × macOS-latest (Xcode pinned). Linux/Windows excluded — spm-cache is macOS-only.
- **Ruby suite:** `bundle install` → `bundle exec rspec`.
- **Swift companion:** `make proxy.build` → `swift test` in `tools/spm-cache-proxy/`.
- **Triggers:** push to `main`, pull requests.
- `update-tap.yml` stays unchanged (release-only).

#### Decision locked — Xcode version pinning
Pin the Xcode version in CI via an `xcode-select` step so the matrix tests a known-good combination. Add a periodic "latest Xcode" canary job to catch Apple-toolchain drift early. Tradeoff: more workflow YAML, but prevents silent breakage on Apple releases.

### Testing `doctor` itself
Each check is a pure function: inject the shell-output collector, assert on the verdict. Fully unit-testable without a real Xcode install. Spec: `spec/doctor_spec.rb` — covers each check's ok/warn/fail paths via injected fixtures.

### Out of scope for v0.3.0
- Content-addressed cache keys (B1) — HIGH effort, deferred to v0.5 (Team Features).
- Selective/partial caching of only-changed deps (B2) — deferred to v0.3.x or v0.4.
- Mergeable libraries support (B3) — parity feature, deferred to v0.4.
- `cachemap --open` visualization (B4) — already partially shipped; polish deferred.
- Non-macOS platforms — out of scope (toolchain is macOS/Xcode).

### Risks & mitigations
- **`watch` FSEvents binding maintenance** — keep the binding minimal (~80 lines); if the native surface proves brittle, fall back to the `listen` gem behind a feature flag. Mitigation: `--once` keeps the core path testable without the OS API.
- **GitHub Action Xcode/runner drift** — keep the Action thin (shell-out only); pin the gem version in the Action so a broken gem release can't break CI silently.
- **`doctor` checks going stale as Xcode evolves** — data-driven registry + periodic canary job catches drift; checks read version floors from a config table, not hardcoded literals.
- **Ruby↔Swift companion version drift** — `companion_binary` check + a shared version constant closes the gap surfaced in the codebase map.

### Success criteria (v0.3.0)
- `spm-cache watch` detects an SPM-dep add/remove in Xcode and regenerates the proxy without manual re-run.
- `spm-cache init` bootstraps a new project to a working `spm-cache.yml` + seeded lockfile in one command.
- `phuongddx/spm-cache-action@v1` restores/saves cache in CI with a 5-line workflow.
- `spm-cache doctor` produces a green/yellow/red report; `--json` is CI-consumable.
- `ci.yml` runs the full RSpec + `swift test` suite on every PR — the project has a test pipeline for the first time.
